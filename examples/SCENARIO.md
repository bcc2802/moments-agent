# 合成首轮场景：独立顾问的开工清单

本页人物、服务、经历和历史作品全部虚构，没有真实客户、发布记录或经营成效。用于体验和检查流程，不能包装成真实成功案例。

## 演示人物

“合成顾问”是一位虚构的个人创业者，提供流程梳理服务，希望用朋友圈让个人创业者和小团队负责人了解自己怎样做事。读者可能关心开工资料、交付边界和确认方式；这些是演示假设，未经真人调查。

初始化模板已包含这套明确标为虚构的人物资料。`--demo` 额外复制 `examples/history/01.md` 至 `05.md` 的五篇合成作品；它们是只读历史输入，发表状态未知。工作区不会预先有三篇Agent稿件。

## 本次材料

> 以下只用于合成演示：我复查了两份合成交付笔记，发现开工前反复确认同三件事：希望解决什么问题、现有资料在哪里、交付由谁确认。我把它们整理成一页开工清单，暂时还没有实际使用结果。我想表达：模板先帮助把边界说清楚，细节仍要问清，不是拿表格替代沟通。请写给个人创业者和小团队负责人，口语一点，不加咨询邀约，不编客户和节省时间的数据。

## 给 Codex 的请求

在已初始化的演示工作区对 Codex 说：

> 这是明确虚构的演示。读取工作区的个人说明书、目标读者和写作偏好，检索“清单”相关历史，回读1–2篇。按 examples/SCENARIO.md 的本次材料，写过程、判断、读者场景三个不同切口。三稿一次保存并回读，展示完整正文、原编号、标签和位置。不配图，不调用热点，不改历史原文，不操作微信。

你应能看到三条不同切口。下面只说明观察点，不预设模型一定写得合格：

| 稿件 | 可观察的区别 | 不能出现 |
|---|---|---|
| 1：过程 | 从复查笔记到形成三项清单 | 虚构真人对话、客户故事、效果数字 |
| 2：判断 | 说明清单与沟通各自解决什么问题 | 把“模板万能”当结论，改写本人观点 |
| 3：读者场景 | 让读者想起一次开工前确认 | 断言所有客户都有同样问题、强加营销邀请 |

继续说：

> 修改2：保留“清单不能替代沟通”，删掉空泛评价，再具体一点。只改第2稿，展示回读结果。

> 这是本次演示选中的第2稿。保存我的最终文字，暂未真实发表。

如果需要验证发布收尾，再明确说：

> 仍是合成演示，请把本轮第2稿按“模拟已发”处理，验证未选稿备份清理和重复确认幂等。不要把它记录为真人发布案例。

然后重开会话，说“恢复这个演示工作区，查询本轮稿件”。轮号和幸存稿应来自文件，不凭对话记忆补造。第1/3稿被清理后不重新编号，也不静默补回。

## 你在检查什么

确认身份没有串到原作者；历史输入未改；保存后能回读；选择不等于发布；模拟状态仅在隔离演示内；三稿确有不同切口；缺失事实保持未知。合成机械检查不能证明真人文风、付费意愿或朋友圈效果。

## 可选的固定机械演示

如果只想检查存储与恢复，可以在项目根目录PowerShell执行：

```powershell
$MomentsStorageDemo = Join-Path $env:USERPROFILE 'moments-storage-demo'
python -B .\scripts\demo.py --workspace $MomentsStorageDemo
```

脚本要求新的、代码目录以外的路径，拒绝复用已有工作区。它初始化合成数据，保存固定三稿、修改第2稿、检查重新实例化恢复及输入原文不变；默认不改变发表状态。想额外检查模拟发表，另选一个新路径并显式加 `--simulate-publication`。不要指向真实工作区。

固定正文来自 [demo-round.json](demo-round.json)，不是模型现场生成；脚本返回PASS也不能证明真人采用、写作质量或线上热点通过。实际使用仍按上面的自然语言请求生成和审阅。
