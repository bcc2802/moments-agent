# 让它认识你和你的读者

本页的路径、命令和扩展配置针对本地版。云端版使用 D1 与访客 Cookie，部署和数据边界见[云端教程](../cloudflare/README.md)及[隐私说明](PRIVACY.md)。

个人资料只放在代码目录以外的工作区，不需要上传到公开仓库。初始化模板中有明确标为虚构的独立顾问示例：演示可以使用，正式使用必须替换，不能把示例身份当成本人事实。

## 网页只填写三项必填

| 红字“必填”字段 | 对应文件 | 填什么 |
|---|---|---|
| 身份与业务 | `personal/author.md` | 你是谁，正在做什么，为谁提供什么帮助 |
| 目标读者 | `personal/audience.md` | 主要写给谁，可补一句他们关心的问题 |
| 表达偏好 | `archive/_style/00_写作偏好.md` | 希望怎样说话，也可写不想出现的语气与表达 |

三个输入框上方都有红色“必填”，填写并保存后即可用当次材料开始生成。历史作品选填，可稍后到素材库补充。网页只收敛必填项；原先写在Markdown中的目标、禁区、分行习惯和其他扩展资料不会因简化表单而清空。

工具使用者与朋友圈读者是两层人。你可能是顾问，读者可能是小团队负责人；不要直接沿用虚构顾问的读者，也不要把所有人都写成潜在客户。

直接对 Codex 说“我目前是……，读者主要是……，我不想公开……，请只更新本工作区对应的三份资料，并回读给我看”。你也可以自己编辑普通 Markdown。

起步不需要完整商业计划、效果数据或历史作品；如尚无明确产品，就如实描述当前身份与正在做的事。不要为了通过必填而补造经历。日后愿意补充历史时，先选一篇能代表自己表达的作品即可，不必一次整理完整作品库。

## 每次写作还需要什么

提供本次的事实、观点、读者与公开边界。个人说明书不代替当次表达，历史作品不证明你今天仍持相同观点。不要让Agent把旧客户、旧业绩、他人经历搬到新稿。

Agent 应按需读取三份短资料及最多两篇参考原文。参考来自本人导入作品和本人明确确认已发的最终稿；未选、选中、准备发、未发终稿及显式keep草稿不参与后续参考。没有合适材料时如实说明，不遍历整台电脑或把全部历史塞进上下文。

## 写作偏好只维护一个入口

`archive/_style/00_写作偏好.md` 是唯一偏好入口，不再创建一份相互冲突的 `personal/preferences.md`。风格案例用于保存本人改稿证据和引用定位，实际终稿仍以原稿Markdown为准。

你回传最终文字时，Agent应按原字、标点和分行保存。明确说“以后都这样写”的偏好与一次性修改分开记录；少量样本只能说明局部观察，不能夸称已经复制你的文风。

“更口语化 / 更真实 / 更专业”是当前稿的三种编辑目标，还可以附加本次意见。它们都保留事实、人称、立场和不确定性，不把“更真实”理解成补造场景或情绪。保存未发终稿不会触发素材入库；只有本人明确确认已发的最终稿才加入后续参考，这属于检索已有写法，不是自动训练模型。

## 自己检查一次

对同一段材料换成另一份明确虚构的身份和目标读者，观察三稿的切口是否随读者问题变化；检查是否还残留合成顾问身份。真实事实不随文风改写，身份资料中的空字段不变成肯定句。

可用只读命令检查三份资料是否能读取：

```powershell
python -B .\scripts\workspace.py profile --workspace $MomentsWorkspace
```

请仅在当前终端已经设置 `$MomentsWorkspace` 时使用；否则把它替换为你的工作区绝对路径。该命令显示个人资料，输出可能含私有内容，反馈故障时不要直接公开粘贴。
