# 热点来源与扩展路线

热点是可选的选题入口。基础写作可以只用本人输入的材料或实际读取过的公开链接；没有热点环境时不影响三稿、修改和存档。当前候选没有新增数据源，也没有附带原作者的热点安装目录。

## 保留的七源范围

百度、牛客、虎扑、稀土掘金、少数派、微博、知乎。

这七源通过外部 TrendRadar 的 MCP/SDK 接口读取 NewsNow 聚合结果，并非七个平台的官方API。第三方榜单标题只作线索，采集时间不是事件时间或原文发布时间。用户旧称“八个平台”也不能自动开启抖音或B站。

原本机实现使用 TrendRadar 6.11.0 固定提交 `657094ed6a527441b917e16d9497fc8435ed091d`。这是兼容性参考，不代表候选已经在新机器完成该可选部署，也不要求自动升级至上游最新版。[TrendRadar项目](https://github.com/sansan0/TrendRadar)

## 可选接入需要准备什么

1. 在代码与私有内容库之外准备独立的 TrendRadar 安装和虚拟环境，按上游文档及许可核对。安装新依赖前，让Agent给出具体安装清单、位置与影响。
2. 只启用上述七ID并配置预期域名；保留RSS、定时、通知、AI分析和翻译关闭，存储为本地且不拉取远端。
3. 本机 `trendradar.local.json` 只记录独立安装的 `root` 和 `python` 绝对路径，不加入发行文件。原生MCP连接同样由使用者在自己的宿主中配置。
4. 先检查配置和服务状态，再单独验证实时采集。仅有配置文件或能列工具不代表采集通过；上游 `save_to_local=false` 仍可能写自身隔离output/SQLite。
5. 检查部分来源失败、原文不可读与空批次的可理解提示，不能用旧榜填补失败或冒充今天的结果。

客户端源码保留安装探测入口 `trendradar_client.py --mode probe`；它不是自动安装器。新用户完成上述可选配置前，热点应标为“尚未配置/待验证”。不把本地基础演示的成功算作联网热点验收。

## 推荐和写稿是两步

推荐时只读公开候选池，按目标读者逐项评价、去重并展示明确批次。最多10条，不足不凑数。选中以后实际读取原链接，重要、争议或高风险主张补一手核验，再确认本人观点或明确的客观讨论方式。三稿不能只根据标题生成事实陈述。

跨会话使用持久化的批次、候选号和准备记录。旧菜单不覆盖新批次或后来已发状态。来源失败、网络失败、解析失败应按实际证据报告，不能自行推断故障原因。

## 有哪些渠道可以增加

以下是研究路线，**不是候选已经接入的功能**。

| 顺序 | 候选 | 接入考虑 |
|---|---|---|
| 先研究原链路 | V2EX、IT之家、36氪、澎湃 | NewsNow源目录已有登记，可按目标读者选2–3个试点；登记不等于公共服务逐源实测成功 |
| 深度与一手材料 | 作者/企业官方博客、公告的RSS/Atom | 上游TrendRadar支持RSS，但当前客户端显式禁用，需要新来源类型、配置保护和测试 |
| 特定读者 | GitHub Trending、Hacker News | 更适合独立开发和AI实践场景，避免技术源数量支配普通朋友圈选题；HN另有官方API |
| 后续研究 | 公众号、X、生财、小红书等 | 先支持本人材料、公开链接或已授权导出；自动渠道逐项核对接口、账号、费用与条件 |

[NewsNow源目录](https://github.com/newsnext/newsnow/blob/main/shared/sources.json) · [Hacker News官方API](https://github.com/HackerNews/API)

[RSSHub](https://github.com/DIYgod/RSSHub)可作订阅扩展研究，路由可用性、登录依赖与维护成本逐项判断。[Product Hunt官方API](https://api.producthunt.com/v2/docs)需要认证，并有商业用途条件，暂不作为默认接入项。

不能只把新名字加进配置。实现前需统一来源ID、provider、原链接、发布时间或null、采集时间、排名或null、核验状态与失败原因；热榜、订阅文章和一手证据分别标识，不直接比较各平台热度。修改来源注册、域名保护、历史兼容、限流、超时、去重与完整池评价后，再单独验收。

可先观察每个新源的真实响应、原文可读率、重复情况和读者相关性；单次成功不证明长期稳定。扩源不连带启用定时、通知、外发或付费模型。
