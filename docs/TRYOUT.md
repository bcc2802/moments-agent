# 陌生用户冷启动试用

本页的路径、命令和扩展配置针对本地版。云端版使用 D1 与访客 Cookie，部署和数据边界见[云端教程](../cloudflare/README.md)及[隐私说明](PRIVACY.md)。

本文件是一份可执行试用脚本和反馈表，尚未代表已经招募或完成真人试用。由作者决定邀请对象并自行联系；维护者不因有此脚本就自动联系他人。

试用目标：验证个人创业者、顾问或服务者能否只靠候选包文档完成第一次写作，并理解稿件和历史的状态。首轮使用本人愿意交给模型的非敏感资料与材料，不要求发布朋友圈或提交私人日记；合成验收另由维护者在隔离工作区完成。

## 准备

由维护者提供同一份候选包、对应 README 和版本标识。使用者在新目录中操作，不复制作者的真实配置、旧 state、私人模板或已发稿。

本次按 [安装指南](INSTALL.md)双击正式入口 `start.cmd`。在“个人说明书”保存自己的资料，“素材库”可跳过，再到“开始写作”生成和改稿，最后在“我的内容”回读。高级使用者可另测 Codex 对话入口。不要要求试用者寻找已移除的示例填充按钮、Demo 徽标或模拟发表按钮。

记录操作系统、Python 版本、Agent 宿主及版本、候选版本；不记录账号凭证。若需要账号或付费计划，先按文档明确说明，由试用者自主决定是否继续，维护者不代注册、不购买。

观察者不抢先解释文档。遇到卡点先记下当前步骤、使用者理解和错误提示，再按需帮助；帮助过的步骤不能记为独立完成。

## 任务 1：理解它能做什么

只读 README，回答：它能帮你处理哪类材料？谁决定最终正文？正文和历史存在哪里？它会不会自动操作微信？

通过标准：使用者能说清材料到候选、本人审稿、手工发布与本人确认的基本关系。若回答依赖观察者纠正，记录缺失的文档位置。

## 任务 2：准备正式工作区并保存说明书

按 README 的快速开始打开正式工作台，在新工作区填写本人不敏感的身份、读者和表达偏好并保存。查看保存提示；旧作品可暂不导入，不因空素材库阻断第一轮。需要与已有使用隔离时，按安装指南指定另一个新工作区，不删除或重置已有资料。

通过标准：无作者机器绝对路径依赖；写入均在试用工作区；没有要求真实日记录或客户信息。若出现安装失败，记录完整错误类型和必要上下文，先移除用户名、token、私人路径和原文。

## 任务 3：从材料得到三稿

在“开始写作”输入一段本人愿意使用的材料与观点，让 Agent 读取说明并产出三个不同切口。记录实际模型返回；开发者固定示例脚本的结果不能混入这项使用者试用。

使用者指出每稿对应的材料依据、不同之处，以及有哪些句子需要本人确认。没有依据的客户、经历或结果不得接受为事实。

通过标准：三稿可回读，角度存在实质差异；无编造经历/客户/效果；使用者知道稿件尚未发表。

## 任务 4：选稿、修改和终稿

先选一稿或说“准备发”，查看发布状态；再给一条具体修改意见，保存并回读终稿。随后重新进入工作区，找回这轮内容。

通过标准：选稿/准备发不会标为已发布；修改意见不被误存成完整正文；重开后能找回正确稿件，编号与当前轮次明确。临时候选保留、清理和备份方式能在文档中找到。

## 任务 5：理解历史与发布确认

在“我的内容”定位终稿，注意页面只显示最近最多10篇、搜索只覆盖已加载内容。首轮试用无需真实发布，因此不操作真实“已发”确认。发布机制模拟另由维护者用隔离合成脚本/测试完成，不能在正式界面假报已发或计入真人发表。

通过标准：历史正文与文件回读一致；使用者理解未发表就不确认已发，未知发表时间不补造。

## 任务 6：补充说明书与公开边界

在已保存说明书上补充不敏感的写作目标、读者问题、文风和禁区；真实客户姓名、联系方式、收入、私聊和日记可保持空缺。检查 Agent 能否说明哪些资料缺失、哪些表述不能代为编写。

通过标准：不依赖完整个人隐私资料才能运行；缺资料有诚实的替代路径；旧示例经历不会混入自己的正文。

## 任务 7：可选的热点入口

基础文字闭环通过后再试。先手工提供可公开访问的链接；只在作者已同意的范围内启用外部热点能力。遇到失败时检查能否明确区分采集失败、原文未读和事实未核验。

通过标准：热榜标题只作线索；来源、本人观点和事实边界清楚；没有热点也不阻断已有材料写作。没有实际启用的来源记“未测”。

## 如何形成结论

维护者按试用记录修订文档或实现，记录问题、修改和复测。结果至少区分：脚本/测试通过、观察者协助下完成、陌生用户独立完成、实际模型写作和真实发布。不要用任一项替代其他项。

对外引用试用反馈、原话、截图或身份需要对应使用者的明确同意。没有同意就只保留内部脱敏问题记录，不把试用变成营销案例。
