# 可选功能支持范围

本页的路径、命令和扩展配置针对本地版。云端版使用 D1 与访客 Cookie，部署和数据边界见[云端教程](../cloudflare/README.md)及[隐私说明](PRIVACY.md)。

先用自己的材料完成基础写作，再决定是否加热点、配图和飞书。候选保留代码接口不等于已经交付跨机器的一键服务，未验证能力应在实际安装中明确显示。

| 功能 | 候选包含什么 | 使用者额外需要什么 | 缺少时怎样继续 |
|---|---|---|---|
| 基础写作 | Skill、个人资料模板、Python存储/状态、Markdown工作区 | Codex宿主与可用账号、Python | 模型不可用时只能诊断和读取，脚本不自行生成文案 |
| Obsidian | Markdown格式和既有标签/查询接口 | 需要时自行使用Obsidian与其CLI | 用普通文件夹读取，说明CLI查询限制 |
| 七源热点 | 来源策略、归一化、选题与准备接口 | 独立TrendRadar/NewsNow链路、自己的可选MCP配置 | 用本人材料或公开链接；不静默使用旧榜 |
| 本地图片处理 | 图片与媒体存档接口、既有图像操作代码 | 选择该功能时需Pillow，及有权使用的图片 | 不配图或保留已有图片；不阻塞正文 |
| 网页首图与补图 | 媒体准备记录、明确轮次和采用记录 | 实际可用的浏览器/截图工具、可访问页面及图片使用范围 | 如实说明无法截图；不用生成图冒充现场 |
| 飞书话题 | 核心任务、终稿与话题绑定接口 | 自己的应用、群、权限、连接与托管设计 | 继续桌面Codex使用；本候选未打包私人托管进程 |
| 电影日签 | 本地竖版海报、`python -m daily_card`、内置片单与句库 | Pillow；想要真实剧照时自备 TMDB API Key；中文字体可自动下载 Noto Sans SC | 没有密钥时仍可生成示例海报；不阻塞写作，也不代发朋友圈 |

## 配图

先交付完整三稿，再按本人要求处理图片。已有图片由本人明确要求使用时，保留要求和原字节，不擅自替换。新的网页首图需要实际页面与完整上下文，不能用想象的截图代替。

原工作流的网页首图标准是完整原样展示页面、保留Logo与其他内容，只给原标题加红框；相关素材需另核对公开使用范围。补图以读者看点、信息增量与共鸣为标准，不凑数量，不拿产品目录制造不必要的销售感。

浏览器支持、页面登录、图片权限和截图尺寸会因环境变化。本候选不承诺所有网站通用截图，也不附带付费图像生成服务。图片准备不改变发表状态；实际采用哪些图片只按本人明确报告记录。

## 飞书高级集成路线

先在桌面验证基础闭环，再评估消息入口。建议按一个话题一个任务绑定来源、轮次、候选、最终文字和发布确认；同话题后续不能套用全局最新稿号。

使用者需要自己控制的飞书组织/应用、目标群、本人身份与权限。后续桥接应复用核心API，分别处理入站身份、持久队列、受控执行、回传幂等、超时和托管恢复。账号、权限申请、发消息和安装后台服务均需相应授权。

本候选没有复制原作者的应用ID、群ID、Hermes profile、Windows计划任务或托管配置。核心 `task-*` 接口与 `_tasks/<task_id>/final.md` 语义可供开发者接入，不能据此宣称新用户飞书端到端已经通过。没有选稿号的本人终稿也应独立保存，不强迫编造编号。

## 怎样记录支持状态

分别标记“代码接口存在”“本机配置完成”“隔离机械验证”“真实在线验证”“真人采用”。它们不能互相替代。只描述实际支持的环境，其他系统、宿主和连接列为待验证；不要为了补齐可选矩阵拖住基础发行候选。
